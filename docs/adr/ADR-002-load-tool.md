# ADR-002 — Load Testing Engine

**Date:** 2026-08-31  
**Status:** Approved (Phase 6)  

## Context
We require a performance engine to execute the 1-VU Baseline and the 20-VU concurrent load test modeling Scenarios A, B, and C. The engine must prevent data collision, handle isolated tokens, and provide P99/P95 histogram metrics.

## Candidates Evaluated
1. **k6:** Purpose-built load testing tool written in Go with JS scripting. Natively supports VUs, execution profiles, and percentile histograms.
2. **Artillery:** Node.js based load testing tool. Good for HTTP, but VU isolation model is less strict than k6.
3. **Playwright-based runner:** Re-using the functional tool for load testing. Rejected because Playwright is not a load generator and lacks native latency histograms at scale.

## Decision
**k6** is selected as the load testing engine.

## Justification
- k6 is specifically designed for the VU model required by our workload definition.
- Natively supports P50/P90/P95/P99 latency calculations.
- Execution profiles (ramp-up, steady-state, ramp-down) map perfectly to k6's `stages` configuration.

## Consequences
- The project will maintain two separate execution engines (Playwright for functional, k6 for load).
- To prevent duplication, both tools will consume the `normalized-api.json` artifact generated by the custom TypeScript parser (Phase 7), ensuring both frameworks test the exact same endpoints.
