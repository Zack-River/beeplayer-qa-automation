## Notes on Workflow Modeling

- **CWF-01 through CWF-04 (Auth):** These are prerequisite workflows. Almost all other workflows require one of these to succeed first. The token extracted here must be injected into the `Authorization` header of subsequent steps.
- **CWF-05 through CWF-07 (Lifecycles):** These workflows represent the core CRUD operations. They will require strict isolation and cleanup (Phase 8/9 implementation) because they mutate state (`REQUIRES_CLEANUP` safety flag).
- **CWF-10 (Bank Transfer):** This is a multi-actor workflow. It requires a Reseller to make a purchase, and an Admin to process it. Testing this will require switching principals mid-workflow.
- **CWF-11 and CWF-12 (Content):** These workflows are read-only (`SAFE`), but they depend on a valid `playlistId` being generated by CWF-07 or pre-seeded.

Next, we proceed to Phase 4 (Risk Analysis + Safety Requirement Definition) where these candidate workflows will be evaluated for runtime safety constraints.
